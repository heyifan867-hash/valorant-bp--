# 一、项目概况

| 项目 | 说明 |
|---|---|
| 名称 | 蓝猫电竞 · 无畏契约 BP 工具 |
| 线上地址 | https://valorant-bp.onrender.com |
| 管理后台 | https://valorant-bp.onrender.com/admin |
| 源码仓库 | https://github.com/heyifan867-hash/valorant-bp-- |
| 技术栈 | Node.js 18+（仅依赖 `ws`、`redis` 两个包）＋ 原生 HTML/CSS/JS 前端，无前端框架、无构建步骤 |
| 实时通信 | WebSocket（路径 `/ws`） |
| 数据存储 | Redis（设置 `REDIS_URL` 时）或本地 JSON 文件（未设置时） |
| 当前部署 | Render（新加坡节点，Docker）＋ Render Key Value（Redis） |

**一句话说明：** 一方创建房间，得到 6 位数字房间号；另一方输入房间号进入，双方各自填写战队名入座，摇骰子决定先手，然后按赛制轮流禁图、选图、选边。所有规则由服务器判定，双方页面实时同步。每场完成的 BP 自动记录，管理后台可查看，记录保留 5 天后自动删除。

# 二、功能清单

**玩家端（首页 `/` 与房间页 `/r/房间号`）**

- 创建房间：选择赛制（BO1 / BO3 / BO5）、地图池、先手方式、每步限时
- 加入房间：首页输入 6 位房间号
- 入座：在空位填写战队名后入座；每个座位只能一人；刷新或断线重连后保持原座位
- 摇骰子决定先手（默认），或抛硬币、指定 A 方 / B 方先手
- 轮流禁图、选图；每选一张图由对手选择开局阵营（进攻 / 防守）；最后剩下的一张为决胜图
- 每步限时，超时由服务器随机代选
- 操作需点两次确认，防止误触
- 顶部地图进度条、回合提示与倒计时（手机端固定在屏幕顶部）
- 完成后：生成结果图（手机长按保存）、复制文字结果

**房主（创建房间的人）**

- 把占错位置的人移出座位
- 不等准备直接开始
- 撤销上一步（BP 进行中或完成后都可用）
- 重置房间（重新开始一场）
- 复制 OBS 直播画面地址

**直播画面（`/obs/房间号`）**

- 给 OBS「浏览器」来源使用，1920×1080，背景透明
- 实时显示双方战队名、每张图的禁 / 选 / 决胜、选边结果、当前回合与倒计时
- 地址加 `?pos=top` 可将信息条放到画面顶部

**管理后台（`/admin`）**

- 密码登录（密码来自服务器环境变量 `ADMIN_PASSWORD`）
- 近 5 天 BP 场数、进行中房间数、最常选 / 最常禁地图
- 每张地图的选图 / 决胜 / 禁用次数统计
- 最近的房间列表（可点进观战）
- BP 记录：搜索、按赛制筛选、查看详情、单条删除、清空、导出 CSV
- 每条记录自 BP 首次完成起保留 5 天，到期自动删除

# 三、BP 规则（核心逻辑）

> 以下规则全部在服务端 `server.js` 中判定，客户端只负责展示和发送操作请求。

## 3.1 步骤生成算法（`buildSteps`）

记地图池张数为 **N**，赛制选图次数为 **P**（BO1 = 0，BO3 = 2，BO5 = 4）：

1. 禁图总次数 **B = N − 1 − P**（最后留 1 张为决胜图）
2. 前置禁图次数 **L**：BO1 时 L = B（全部是禁）；BO3 / BO5 时 L = min(2, B)
3. 地图操作顺序：先 L 次禁 → 再 P 次选 → 再 (B − L) 次禁
4. 双方**轮流**执行地图操作（禁或选），从先手方开始交替
5. 每次**选图**之后，立即插入一个**选边**步骤，由**对手**选择开局阵营
6. 所有地图操作结束后，剩下的 1 张自动成为**决胜图**（无人操作）
7. 决胜图的选边由「最后一次地图操作方」的**对手**进行

**示例：7 张图、A 方先手**

| 赛制 | 步骤顺序 |
|---|---|
| BO1 | A禁 → B禁 → A禁 → B禁 → A禁 → B禁 → 决胜图（自动）→ A选边 |
| BO3 | A禁 → B禁 → A选 → B选边 → B选 → A选边 → A禁 → B禁 → 决胜图（自动）→ A选边 |
| BO5 | A禁 → B禁 → A选 → B选边 → B选 → A选边 → A选 → B选边 → B选 → A选边 → 决胜图（自动）→ A选边 |

地图池最少张数：BO1 ≥ 2，BO3 ≥ 3，BO5 ≥ 5。张数不是 7 时，禁图次数按上面公式自动调整。

## 3.2 先手方式

| 方式 | 规则 |
|---|---|
| 摇骰子（默认） | 双方准备后进入摇骰子阶段；每方点「摇骰子」得到 1–6 的随机数（服务端用 `crypto.randomInt` 生成）。双方都摇完后：点数大的一方先手，3.2 秒后自动进入 BP；点数相同则显示平局，2.6 秒后自动清空重摇 |
| 抛硬币 | 每次开始新一场时由服务端随机决定 |
| 指定 A 方 / B 方 | 固定先手 |

## 3.3 限时

- 可选：不限时、20、30、45、60、90 秒（默认 30 秒）
- BP 阶段某一步超时：服务端从当前可选项中**随机**替该方选择，并标记为「超时代选」
- 摇骰子阶段超时：未摇的一方由服务端代摇
- 倒计时以服务端时间为准，客户端用 `serverNow` 校正本地时钟偏差

## 3.4 座位与身份

- 房间刚创建时 A、B 两个座位都是空的，显示为「A 方」「B 方」
- 任何进入房间的人默认是**观战**身份；在空位填写战队名后入座，成为该方队长
- 入座时服务端生成该座位的密钥（token），保存在该用户浏览器本地；重连时带上密钥即恢复身份
- 一个座位只能被一人占用；一人只能占一个座位
- 开始前本人可离开座位；房主任何时候都可把人移出座位（BP 进行中移出后，该位置可由新人重新入座接手）
- 离开座位后，该位置名称恢复为「A 方 / B 方」

## 3.5 房主操作

- **撤销上一步**：退回到最近一次有人操作的步骤，清空该步及之后所有结果（包括自动生成的决胜图），由原来那一方重新操作。BP 完成后也可撤销
- **重置房间**：清空所有结果、准备状态和骰子，房间进入新的一场（场次号 +1）；座位和战队名保留
- **直接开始**：跳过准备，直接进入摇骰子或 BP

## 3.6 房间生命周期

- 房间号：6 位数字（100000–999999），随机生成且不重复
- 房间状态：`waiting`（等待准备）→ `dice`（摇骰子，仅骰子模式）→ `running`（BP 中）→ `done`（完成）
- 房间 12 小时无人使用且无人在线时自动清理
- 每次状态变化都会保存；服务器重启后房间自动恢复，客户端自动重连

# 四、数据结构

## 4.1 房间状态（服务端推送给客户端的 `state`）

```json
{
  "id": "385172",
  "config": {
    "format": "bo3",
    "pool": ["Tianshu", "Bind", "Haven", "Lotus", "Sunset", "Abyss", "Corrode"],
    "timer": 30,
    "firstMode": "dice",
    "first": "A",
    "teamNames": { "A": "蓝猫电竞", "B": "夜猫子" }
  },
  "steps": [
    { "kind": "map", "action": "ban", "team": "A", "value": "Abyss", "auto": false },
    { "kind": "map", "action": "pick", "team": "A", "value": "Haven", "auto": false },
    { "kind": "side", "team": "B", "mapStep": 2, "value": "attack", "auto": false },
    { "kind": "decider", "value": null }
  ],
  "cursor": 3,
  "status": "running",
  "dice": { "A": 5, "B": 4, "round": 1, "ties": [], "winner": "A" },
  "ready": { "A": true, "B": true },
  "deadline": 1762000000000,
  "serverNow": 1761999975000,
  "online": { "A": 1, "B": 1, "spec": 2 },
  "seats": { "A": true, "B": true }
}
```

| 字段 | 说明 |
|---|---|
| `steps[].kind` | `map` 地图操作 / `side` 选边 / `decider` 决胜图（自动） |
| `steps[].action` | `ban` 禁 / `pick` 选（仅 `map`） |
| `steps[].team` | 执行方 `A` / `B` |
| `steps[].mapStep` | 选边步骤对应的地图步骤下标 |
| `steps[].value` | 地图 id，或选边结果 `attack` / `defense` |
| `steps[].auto` | 是否为超时代选 |
| `cursor` | 当前待操作的步骤下标 |
| `deadline` | 当前步骤截止时间（毫秒时间戳），不限时为 `null` |

## 4.2 BP 记录（管理后台）

```json
{
  "id": "385172-1",
  "roomId": "385172",
  "game": 1,
  "createdAt": 1761990000000,
  "finishedAt": 1761990600000,
  "firstFinishedAt": 1761990600000,
  "expiresAt": 1762422600000,
  "format": "bo3",
  "pool": ["Tianshu", "..."],
  "timer": 30,
  "firstMode": "dice",
  "first": "A",
  "teamNames": { "A": "蓝猫电竞", "B": "夜猫子" },
  "dice": { "A": 5, "B": 4, "winner": "A", "ties": 0 },
  "maps": [
    { "map": "Haven", "by": "A", "sideBy": "B", "side": "attack", "attack": "B", "auto": false },
    { "map": "Corrode", "by": null, "sideBy": "A", "side": "defense", "attack": "B", "auto": false }
  ],
  "bans": [ { "map": "Abyss", "team": "A", "auto": false } ],
  "autoSteps": 0,
  "undos": 1
}
```

- `maps` 按比赛顺序排列，`by` 为 `null` 表示决胜图；`attack` 为进攻开局方
- `expiresAt` = 首次完成时间 + 5 天；房主撤销后重新完成只更新内容，不重置过期时间
- Redis 中键名为 `vbp:rec:<id>`，用 Redis 过期时间自动删除

## 4.3 地图数据（`data.js`）

```js
{ id: 'Tianshu', zh: '天枢云阙', img: '/maps/tianshu.webp' }
```

共 13 张地图，图片均为 1280×720 WebP，位于 `public/maps/`。`DEFAULT_POOL` 为建房时默认勾选的 7 张：天枢云阙、源工重镇、隐世修所、莲华古城、日落之城、幽邃地窟、盐海矿镇。

# 五、接口

## 5.1 HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/meta` | 地图列表与默认地图池 |
| POST | `/api/rooms` | 创建房间。请求：`{format, pool, first, timer}`；返回：`{id, adminToken}` |
| GET | `/api/rooms/:id` | 房间是否存在（200 / 404） |
| POST | `/api/admin/login` | 后台登录。请求：`{password}`；返回：`{token, exp}`（12 小时有效） |
| GET | `/api/admin/overview` | 后台数据（需 `Authorization: Bearer <token>`） |
| DELETE | `/api/admin/records/:id` | 删除单条记录 |
| DELETE | `/api/admin/records` | 清空全部记录 |

页面路由：`/` 首页，`/r/:id` 房间页，`/obs/:id` 直播画面，`/admin` 管理后台。

安全措施：同一 IP 每小时最多建 60 个房间；后台登录失败 8 次锁定 15 分钟；后台令牌为 HMAC 签名。

## 5.2 WebSocket 消息（路径 `/ws`，JSON 格式）

**客户端 → 服务端**

| type | 参数 | 谁可以发 | 说明 |
|---|---|---|---|
| `join` | `room, token?, adminToken?` | 所有人 | 进入房间；带座位密钥恢复队长身份，带房主密钥获得房主权限 |
| `claim` | `team, name` | 观战者 | 入座并设置战队名 |
| `release` | `team` | 本人 / 房主 | 离开座位 / 移出座位 |
| `ready` | `value` | 队长 | 准备 / 取消准备 |
| `roll` | — | 队长 | 摇骰子 |
| `act` | `value` | 当前回合的队长 | 禁图、选图（地图 id）或选边（`attack` / `defense`） |
| `undo` | — | 房主 | 撤销上一步 |
| `reset` | — | 房主 | 重置房间 |
| `start` | — | 房主 | 直接开始 |

**服务端 → 客户端**

| type | 内容 | 说明 |
|---|---|---|
| `joined` | `role, admin, token?, released?` | 身份确认；入座时下发座位密钥 |
| `state` | `state`（见 4.1） | 每次房间变化都向房间内所有人推送完整状态 |
| `error` | `code, message` | `no_room` 房间不存在；`bad_action` 操作不合法（附中文提示） |

# 六、部署

## 6.1 环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `PORT` | 否 | 监听端口，默认 3000 |

## 6.2 运行方式

```bash
npm install
npm start
```

或使用仓库中的 Dockerfile：

```bash
docker build -t valorant-bp .

```

反向代理（Nginx / Caddy）需要支持 WebSocket 协议升级，路径为 `/ws`。

# 七、接入微信小程序的方式

## 方案一：web-view 嵌入现有网页（推荐，改动最小）

**前提：** 小程序为企业或个体工商户主体（个人主体不支持 web-view）。

**步骤：**

1. 准备一个**已完成 ICP 备案**的域名，例如 `bp.你的域名.com`
2. 将本项目部署到国内服务器（备案要求），并配置 HTTPS 证书（WebSocket 同时为 wss）
3. 小程序后台 → 开发管理 → 开发设置 → **业务域名**，添加上述域名；下载校验文件，放到项目的 `public/` 目录根下（会以 `https://域名/校验文件名.txt` 访问到），重新部署后点击保存
4. 小程序中新增一个页面，例如 `pages/bp/bp`：

```xml
<!-- pages/bp/bp.wxml -->
<web-view src="{{url}}"></web-view>
```

```js
// pages/bp/bp.js
const BASE = 'https://bp.你的域名.com';
Page({
  data: { url: BASE },
  onLoad(q) {
    // 支持从分享卡片直接进入房间：pages/bp/bp?room=385172
    this.setData({ url: q.room ? `${BASE}/r/${q.room}` : BASE });
  },
  onShareAppMessage(opt) {
    // opt.webViewUrl 为当前网页地址，可解析出房间号用于分享
    const m = (opt.webViewUrl || '').match(/\/r\/(\d{6})/);
    return {
      title: m ? `来蓝猫 BP 房间 ${m[1]} 开 BP` : '蓝猫电竞 · 无畏契约 BP 工具',
      path: m ? `/pages/bp/bp?room=${m[1]}` : '/pages/bp/bp',
    };
  },
});
```

5. 在小程序首页或菜单中加一个入口跳转到该页面

**说明：**

- 网页内的 WebSocket、localStorage（座位身份）在 web-view 中正常工作
- 「生成结果图」在 web-view 中可用，用户长按图片即可保存或转发
- 管理后台 `/admin` 和直播画面 `/obs/房间号` 不需要放进小程序，继续用浏览器访问即可
- 使用第三方搭建平台的，通常有「网页 / 外链」组件，填写上述地址即可，同样需要先配置业务域名

## 方案二：原生小程序 + 微信云开发（个人主体可用，无需域名与备案）

将前端改写为小程序原生页面，后端改写为云开发：

| 现有实现 | 云开发对应 |
|---|---|
| WebSocket 实时推送 `state` | 云数据库 `rooms` 集合 + 客户端 `db.collection('rooms').doc(id).watch()` 实时监听 |
| 客户端发送 `act / roll / claim …` | 调用云函数（如 `bp`），在云函数中执行与 `server.js` 相同的校验逻辑后更新数据库 |
| 座位密钥 token | 直接使用云函数中的 `OPENID` 识别身份，更简单可靠 |
| 服务端计时器（超时代选） | 云函数中写入 `deadline`；任一客户端倒计时结束时调用云函数「检查超时」，云函数校验已超时后代选 |
| BP 记录 + 5 天过期 | 云数据库 `records` 集合 + 每天执行一次的定时触发云函数，删除 `expiresAt` 已过的记录 |
| 管理后台 | 小程序内仅管理员 OPENID 可进入的页面 |
| 结果图 | 小程序 canvas 绘制后 `wx.saveImageToPhotosAlbum` 保存到相册 |
| 分享进房 | `onShareAppMessage` 返回带房间号的 path |

`server.js` 中的 `buildSteps`、`optionsFor`、`applyAction`、`rollDice`、`undoLast`、`recordGame` 为纯逻辑函数，可直接复制到云函数中复用。直播画面（OBS）无法在小程序实现，建议保留网页版。
